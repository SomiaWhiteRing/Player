# Maniac 250921 运行兼容性评估与实施顺序

日期：2026-09-22。评估对象是当前 Player 工作区和 RPGRewriter-maniac 的已审核分析资料。本文件及配套 CSV 是实施前的静态清单，不是兼容性验收报告。

## 结论

可以依据这份报告开展系统性的 Maniac 兼容实现。250921 的指令字段、文本布局、模式和相关运行时消费者已有足够扎实的起点，现有 Player 也能复用大量地图、战斗、图片、字符串和存档设施。

“完整兼容”仍需要逐子模式实现、补齐共享运行环境，并与固定版本的原版比较可观察行为。报告的结构分析完整，不等于 Player 的运行语义已经完整；仅依据这些资料，也不能承诺所有 Maniac 版本、第三方插件和平台完全等价。

建议首先固定 **patch_selfvar_250921、Windows 上的原版可观察行为** 作为基准，然后分别验收 Web / Android。跨平台差异须逐项列出；存在功能缺口的平台不能标为完整兼容。241028 单列版本差异和回归，不直接套用 250921 的完成状态。

P1 必须先建立正确的运行环境。否则即使给 3036 添加入口，其他命令的负编号读取、嵌套调用和返回值仍会读写错误的位置。P3/P4 可以按不依赖未完成基础设施的具体子项调整先后，但本轮没有委托子代理。

实现复用现有事件解释器、图片、地图和战斗系统；共享解析/求值逻辑只在有共同契约的地方抽取。报告用于提供规范和追溯，不要求运行游戏时加载分析 JSON，也不要求把 RPGRewriter 的 C# codec 架构搬进 Player。

每批结束交付：范围内的代码、更新后的子模式矩阵、验证证据、未通过项。阻止本批正确性的发现作为 blocker；无关功能另列。未达到验收不能标完成；达到约定验收后停止本批扩展。

## 完整兼容所需的验收

1. 参数与结果：缺省零、模式局部差异、间接/负编号、范围/别名、文本编码、数组和表达式副作用。
2. 执行状态：指令游标、调用栈、等待/重试、钩子顺序、帧间可见状态；空操作也需核对取指方式。
3. 持久化：相关状态在保存、退出、读档后正确恢复；原版 Maniac 存档互读作为独立目标，不能用 Player 自己的存档扩展替代其结论。
4. 表现与平台：字体和文字布局、截图像素、图片层次、缩放、音画和输入时序，以及文件、窗口和设备接口的实际效果。
5. 回归：原生 2000/2003、当前已支持的 Maniac 游戏和 241028 对照样例分别记录；250921 的结果不能自动覆盖其他版本或第三方插件。

需要新增的专项测试、原版差分执行/人工游戏 UI 验收须在获得用户明确授权后实施，这是当前会话提供的 AGENTS.md 约束。本轮仅整理其验收要求，没有创建测试代码、启动游戏或进行浏览器交互。

对于 Windows 桌面窗口、系统鼠标、文件系统等能力，Web/Android 的平台接口可能无法提供完全相同的可观察行为。需要逐项决定适配方式和验收范围；任何降级都应保留在兼容矩阵中。JS 需要补齐共享上下文和宿主绑定，仅接通源码求值不算完成该命令。

## 本轮完成与未完成

本轮新增此评估文档及 168 行入口 CSV，检查编号唯一性、目录对齐、分派来源和引用文件存在性；没有修改 Player/liblcf 运行时代码。既存未提交修改保持原状。

本轮没有完成逐子模式全量审计、构建、运行时对照或跨平台验收。没有据此给出现有兼容百分比，也没有给出缺乏工作量依据的工期承诺。下一项实际实施应是 P0 的子模式矩阵和 P1 的运行状态设计；进入代码阶段之前先明确目标平台、原版存档互通范围及专项验证授权。
